# Re:Guard EMG 신호 필터링 / 전처리 정리

발표 자료 준비용 기술 문서. 실제 코드(`ESP32_WIFI_code.ino`, Re:Guard 앱 소스) 기준으로 정리했으며,
**중요: 신호 처리 체인이 실제로는 두 곳에 나뉘어 있고, 서로 다른 신호를 처리합니다.** (5번 항목 필독)

---

## 1. 전체 신호 흐름 (Signal Pipeline)

```
근육 (EMG)
  → 전극(Ag/AgCl) 2개 × 3채널 + Ground
  → ADS131M08 (24-bit 동시샘플링 ADC, SPI)
  → STM32F103 (프레이밍: 0xAA 0x55 + 채널당 3바이트, UART 921600bps)
  → ESP32-S3 (Wi-Fi AP + 웹서버)
       ├─ (A) ESP32 자체 뷰어 페이지 (http://192.168.4.1) → 필터링·FFT·특징량 계산 (2절)
       └─ (B) GET /samples JSON API → Re:Guard 앱이 폴링 (5절)
```

- **샘플링 레이트**: FS ≈ 1295 Hz (STM32의 ADS131M08 OSR 설정에 종속. OSR_1024→~1295Hz, OSR_2048→~650Hz, OSR_512→~2578Hz — 발표에는 실제 설정값 명시 필요)
- **ADC → 전압 변환식**: `V(mV) = code × 1200 / 2²³` (VREF=1.2V, PGA=1 기준. PGA를 바꾸면 이 상수도 같이 바뀌어야 함)

---

## 2. 전처리 필터 체인 (ESP32 자체 뷰어 페이지, 클라이언트 JS)

STM32→ESP32로 오는 원시 ADC 값에 대해, **ESP32가 만드는 자체 HTML 페이지(브라우저에서 `http://192.168.4.1` 직접 접속 시)의 JavaScript**가 실시간으로 필터를 적용합니다. RBJ cookbook 공식 기반 2차 IIR(Biquad) 필터를 순서대로 연결(cascade)한 구조입니다.

| 순서 | 필터 | 목적 | 파라미터 | 기본값 |
|---|---|---|---|---|
| 1 | High-pass | DC 오프셋 / 베이스라인 드리프트 제거 | 20 Hz, Q=0.707 (Butterworth) | ON |
| 2 | Notch | 전원 잡음(60Hz 기본파) 제거 | 60 Hz, Q=30 | ON |
| 3 | Comb Notch | 60/120/180Hz 고조파까지 한 번에 제거 | 60/120/180 Hz, 각각 Q=30 | OFF (FFT에서 고조파가 보일 때만 수동 활성화) |
| 4 | Low-pass | EMG 유효 대역 상한 제한, 고주파 잡음 차단 | 450 Hz, Q=0.707 | ON |
| 5 | Rectify | 전파 정류 (절댓값), 활성도 크기 파악용 | `\|x\|` | OFF |
| 6 | Envelope | 정류 신호를 저역통과(≈4Hz)해서 포락선(활성도 추세) 추출 | 지수이동평균, α = 1 − e^(−2π·4/FS) | OFF |

**기본 조합 = HP 20Hz + Notch 60Hz + LP 450Hz** → 20–450Hz 대역통과 + 60Hz 노치. 표면 EMG(sEMG)의 표준적인 전처리 대역(대개 20–450Hz 권장 범위)과 일치합니다.

각 필터는 화면에서 버튼으로 개별 on/off 가능 — 사용자가 신호를 직접 보면서 어떤 필터가 필요한지 판단하도록 만든 디버깅/튜닝 도구입니다.

### 특징량 계산용 "고정 체인" (표시용과 별개)

화면에 표시되는 파형은 위 토글 상태를 따라가지만, RMS/MDF 등 **특징량 계산에는 토글과 무관하게 항상 HP20+Notch60+LP450이 고정 적용**됩니다 (`achain`). 사용자가 Rectify/Envelope 등을 켜서 화면만 다르게 보고 있어도 분석값은 항상 일관되게 나오도록 하기 위함입니다.

## 3. 주파수 분석 (FFT)

- **크기**: NFFT = 1024
- **창함수(Window)**: Hann window (스펙트럼 누설(spectral leakage) 감소 목적, FFT 직전에 적용)
- **알고리즘**: Radix-2 FFT (자체 구현, 반복형)
- **표시**: 100Hz 격자선 + 60Hz 위치에 붉은 마커선(전원 잡음 필터가 제대로 동작하는지 시각 확인용), 약 8fps(120ms 주기) 갱신
- **DC 제거**: FFT 입력 전에 창 구간 평균값을 빼서 DC 성분 제거

---

## 4. 특징량 추출 (Feature Extraction, ~4Hz 주기로 갱신)

고정 분석 체인(HP20+Notch60+LP450) 신호 기준, 최근 NFFT(1024)개 샘플 창에 대해 계산:

| 특징량 | 의미 | 계산 방법 |
|---|---|---|
| **RMS** | 근활성 크기(진폭) | √(Σx² / N) |
| **MAV** (Mean Absolute Value) | 근활성 크기(대안 지표) | Σ\|x\| / N |
| **ZC** (Zero Crossing) | 신호가 0을 가로지르는 횟수 | RMS의 5% 데드밴드 적용(잡음으로 인한 오검출 방지) 후 부호 전환 카운트 |
| **MNF** (Mean Frequency) | 평균 주파수 — 근피로 지표 | PSD(전력스펙트럼밀도) 가중평균 주파수 |
| **MDF** (Median Frequency) | 중앙 주파수 — 근피로 지표 | 누적 PSD가 전체의 50%가 되는 지점의 주파수 |

MNF/MDF는 근피로가 진행되면 저주파 쪽으로 이동하는 특성이 있어 피로도 모니터링에 흔히 쓰이는 지표입니다 — 발표에서 "왜 주파수 특징량을 뽑았는가"에 대한 근거로 언급하면 좋습니다.

## 5. ⚠️ Re:Guard 앱 자체의 신호 처리 — 2절의 필터 체인과 다릅니다

**중요한 구분점**: 2~4절의 HP/Notch/LP 필터·FFT·MNF/MDF 등은 전부 **ESP32가 만드는 자체 뷰어 페이지(`http://192.168.4.1`)에서만 동작하는 JavaScript**입니다. Re:Guard 모바일 앱은 이 페이지를 쓰지 않고, `GET /samples?since=N` API를 직접 폴링해서 **원시(raw) ADC 값**을 받아옵니다 — 즉 **앱으로 들어오는 데이터에는 위 필터들이 하나도 적용되어 있지 않습니다.**

Re:Guard 앱이 실제로 하는 전처리는 다음이 전부입니다:

1. **폴링**: 약 40ms 주기로 `/samples` 호출 (ESP32 뷰어 페이지와 동일한 주기)
2. **단위 변환**: raw code → mV (`code × 1200 / 2²³`, 2절과 동일한 상수)
3. **정류**: 절댓값(`|mV|`) — 필터 없이 바로 정류만 적용
4. **윈도우 RMS**: 한 번의 폴링 응답에 담긴 배치(보통 수 샘플) 전체에 대해 RMS 계산 (필터링된 40ms 배치 RMS)
5. **스케일링**: 사용자가 지정한 "Max Reference (mV)" 값을 100%로 놓고 0–100 활성도(%)로 선형 변환 — 앱 UI 전체가 이 0–100 스케일을 전제로 설계되어 있어서 필요한 단계
6. **캘리브레이션 통계** (Debug Mode에서 20초 정지 상태로 수집): 위 0–100 스케일 값들에 대해
   - `median`, `MAD`(median absolute deviation, 중앙값 절대편차) 계산 — 평균/표준편차보다 이상치(노이즈 튐)에 강건해서 채택
   - `Caution = median + 5×MAD`
   - `Warning = Caution × 1.5`
   - `Release = Caution × 0.7`

**발표 시 주의할 점**: "HP/Notch/LP 필터로 전처리했다"고 말하면 정확히는 ESP32 뷰어 페이지 얘기이고, **Re:Guard 앱 자체의 실시간 알림/캘리브레이션은 대역통과·노치 필터가 없는 raw 정류 RMS 신호**를 씁니다. 두 경로를 구분해서 설명하시거나, 발표 전에 앱 쪽에도 동일한 필터 체인을 이식할지 결정하시는 게 좋습니다 (원하시면 이식 작업 도와드릴 수 있습니다).

---

## 6. 발표용 한 장 요약 (슬라이드용 압축 버전)

- **하드웨어 신호 경로**: ADS131M08(24bit ADC) → STM32(UART 프레이밍) → ESP32(Wi-Fi 송신), FS≈1295Hz
- **필터 체인** (ESP32 뷰어 페이지): HP 20Hz → Notch 60Hz(+선택적 120/180Hz 고조파) → LP 450Hz, 2차 Biquad IIR cascade — 표준 sEMG 대역(20–450Hz) 확보 + 전원 잡음 제거
- **분석**: 1024pt FFT(Hann window) + RMS/MAV/MDF/MNF/ZC 특징량, ~4Hz 갱신 — 근활성 크기 + 근피로 경향 동시 모니터링
- **앱 단 처리**: raw code→mV→정류→구간 RMS→사용자 기준값 대비 0–100% 정규화
- **임계값 산출**: median+5×MAD 기반 통계적 캘리브레이션(이상치에 강건) → Caution/Warning/Release 3단계 히스테리시스 임계값
